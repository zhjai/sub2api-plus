# 运行阈值的定时恢复

当真实请求的错误率或首个输出延迟超过配置阈值且样本足够时，优先低价、优先稳定、避免降智会让账号在普通排序中后移一位。重新评估只能重算已有统计，不能凭空生成恢复证据。

调度策略的“运行阈值”区域可启用定时恢复并设置间隔，默认开启、30 分钟。预设从 5 分钟至 24 小时，也可填写自定义分钟。关闭此选项后保留普通后移规则。自定义平衡按权重排序，不使用这套阈值后移或恢复。

## 工作方式

1. 最新运行样本或上次试用后等待一个恢复间隔。
2. 到期后，下一次合适的真实请求可临时撤销该账号的一位后移，收集新运行样本；没有业务请求就继续等待，不额外调用上游模型。
3. 本实例的同一账号、请求模型及推理强度最多一个定时试用在途。已成功准入会登记试用时间，客户端取消且未产生新样本时退还试用机会。
4. 结果继续更新原有错误率和延迟统计。仍然超标则保留普通后移，等待下个间隔；统计回到阈值内才恢复普通排序。不清空历史错误，也不把试用成功一次标成健康。

## 仍然生效的规则

- “避免降智”保持通过率第一优先，不允许恢复试用越过更高通过率档位。
- 不越过更高的管理员账号优先规则，不绕过分组、平台、模型、能力、并发、RPM、冷却或其他硬限制。
- 既有 Response/任务强制归属保持不变，不为试用迁移已有续接请求。
- 试用未能准入时继续按原排序选择；排队计划也仍使用原排序。

## 页面与记录

排行榜保留普通排序，显示等待试用、可试用或试用中及下次时间。可试用仅代表时间条件满足，并不保证已被选择，也不是健康判定。实际选号实时检查到期与准入条件，不需要等待“立即评估”或下次定时评估。

实际调度记录使用 `runtime_recovery_trial` 原因码标识定时试用；记录中的普通排名可与此次试用选择不同。

配置字段是 `scheduling_thresholds.recovery_enabled` 和 `recovery_interval_seconds`。旧配置缺省时采用开启和 1800 秒。时间受现有整数存储范围约束：300～2147483647 秒，分钟输入上限向下取整。

恢复名额和运行统计均为实例内状态，与现有运行质量统计一致；并非多个实例共用的全局熔断状态。重启会丢失实例内运行统计。主动渠道探针与降智评测不替代这里的真实请求错误率和首个输出测量。
